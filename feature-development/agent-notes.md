# World integration contracts and provenance

Source identities are in [sources.json](integration/sources.json); the [reader index](decisions.md) routes to every complete feature record. Each provenance file identifies the source commit, original Git blob, original/archived SHA-256 and every rewritten link target. All text outside link target spans is preserved. Original documents also remain reachable through preserved merge ancestry.

WINT-001: This is a history-preserving local integration branch. It is not a push target, source checkout update or approval of the combined product. Unique feature files and milestone receipts remain at their original paths. Source-feature evidence retains its original scope; merge success does not establish combined native behavior or tilemap visual acceptance.

WINT-002: The next private consumer should use an asymmetric two-layer fixture, explicit bidirectional key/ID mapping, immutable metadata retention and literal expected values after load/edit/diff/apply/save and a fresh-process reload. Cover unknown keys/IDs, strict limits, differing duplicate semantics and exact-base mismatch. Runtime publication and file replacement have separate transaction boundaries. A separate actual 2D procedural output should map occupancy to semantic terrain labels and storage keys; derived visual IDs are not persisted semantic identities.

No provider, recipe format, sibling branch dependency, public procedural API or graphics acceptance is introduced by this preparation. Worker2 owns the combined consumer and focused native proof under the shared one-job build/resource wrapper.
